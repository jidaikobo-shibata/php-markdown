# Markdownチートシート

この文書では、Markdownの記法と `jidaikobo/php-markdown` によるレンダリング結果を
続けて掲載します。同梱のブラウザーサンプルで開くと独自記法も変換されます。
独自拡張に対応しないリポジトリビューアーでは、意図的に元の文字列が残ります。

## Markdownの基本記法

### 段落と改行

Markdown記法：

```markdown
これは一つの段落です。

これは別の段落です。
この行は同じ段落の続きです。

行末にバックスラッシュを置くと\
明示的な改行になります。
```

レンダリング結果：

これは一つの段落です。

これは別の段落です。
この行は同じ段落の続きです。

行末にバックスラッシュを置くと\
明示的な改行になります。

### 見出し

Markdown記法：

```markdown
# レベル1の見出し
## レベル2の見出し
### レベル3の見出し
```

レンダリング結果：

#### レンダリングされたレベル4の見出し

このページの題名がレベル1、各節の階層がレベル2と3の例です。すべての見出しに
パーマリンクが自動的に追加されます。

### 強調

Markdown記法：

```markdown
*強調*、**重要性の強調**、***両方を組み合わせた強調***。

~~取り消し線~~は対応するGFM拡張が有効な場合にだけ使えます。
```

レンダリング結果：

*強調*、**重要性の強調**、***両方を組み合わせた強調***。

取り消し線は現在このパッケージで有効にしていないため、ここでは記法だけを
示しています。

### リンクと画像

Markdown記法：

```markdown
[リンクの例](https://example.com/ "任意のtitle")

![青い四角](files/sample-image.svg "サンプル画像")
```

レンダリング結果：

[リンクの例](https://example.com/ "任意のtitle")

![青い四角](files/sample-image.svg "サンプル画像")

情報を伝える画像には適切な代替テキストを付けます。空の代替テキスト
`![](image.svg)` は、本当に装飾目的だけの画像に使用します。

### 箇条書きと番号付きリスト

Markdown記法：

```markdown
- 一つ目の項目
- 二つ目の項目
  - 入れ子の項目

1. 最初の手順
2. 次の手順
```

レンダリング結果：

- 一つ目の項目
- 二つ目の項目
  - 入れ子の項目

1. 最初の手順
2. 次の手順

### 引用

Markdown記法：

```markdown
> 引用の中でも **ほかのMarkdown記法** を使えます。
>
> 複数の段落を含められます。
```

レンダリング結果：

> 引用の中でも **ほかのMarkdown記法** を使えます。
>
> 複数の段落を含められます。

引用はほかの情報源から引用した内容に使用し、字下げや装飾だけを目的として
使わないようにします。

### インラインコードとコードブロック

Markdown記法：

````markdown
短いコードには `インラインコード` を使います。

```php
echo 'フェンス付きコードブロック';
```
````

レンダリング結果：

短いコードには `インラインコード` を使います。

```php
echo 'フェンス付きコードブロック';
```

### 主題区切り

Markdown記法：

```markdown
---
```

レンダリング結果：

---

### 表

Markdown記法：

```markdown
| 名前 | 値 |
| --- | ---: |
| アルファ | 10 |
| ベータ | 20 |
```

レンダリング結果：

| 名前 | 値 |
| --- | ---: |
| アルファ | 10 |
| ベータ | 20 |

### 属性

League CommonMarkのAttributes拡張を有効にしています。このパッケージでは
`id`、`class`、`lang`、`title`、`rel`属性を許可しています。

Markdown記法：

```markdown
[英語のページ](https://example.com/){.external lang=en rel=noreferrer}
```

レンダリング結果：

[英語のページ](https://example.com/){.external lang=en rel=noreferrer}

## 見出しパーマリンクと目次

レベル1から6までの見出しには、パーマリンクが自動生成されます。各記号は
キーボードでフォーカスできるリンクになり、対応する見出し本文をアクセシブルネーム
として持ちます。見出しはフラグメントリンクの移動先として利用できます。

次のプレースホルダーを書いた位置にだけ目次を生成します。

```markdown
[TOC]
```

この文書の冒頭にある目次がレンダリング結果です。目次にはレベル2から4までの
見出しを掲載し、一文書につき100項目までに制限しています。

## jidaikobo/php-markdownの独自拡張

### 列見出しと行見出しを持つ表

通常の列見出しには `scope="col"` が付きます。セル末尾にコロンを付けると
`scope="row"`を持つ行見出しになり、記法のコロンはHTMLから取り除かれます。

Markdown記法：

```markdown
| 曜日 | 開館 | 閉館 |
| --- | --- | --- |
| 月曜日: | 09:00 | 17:00 |
| 火曜日: | 10:00 | 18:00 |
```

レンダリング結果：

| 曜日 | 開館 | 閉館 |
| --- | --- | --- |
| 月曜日: | 09:00 | 17:00 |
| 火曜日: | 10:00 | 18:00 |

### 表のcaption

表の直前に空行を挟まず、強調だけの段落を置きます。caption内のリンクやコードも
構造を維持します。

Markdown記法：

```markdown
*2026年の地域別人口*
| 地域 | 人口 |
| --- | ---: |
| 東 | 12 |
| 西 | 8 |
```

レンダリング結果：

*2026年の地域別人口*
| 地域 | 人口 |
| --- | ---: |
| 東 | 12 |
| 西 | 8 |

バージョン1のcaption行記法も互換性のため利用できます。

```markdown
| 名前 | 値 |
| --- | --- |
| アルファ | 10 |
|: 従来形式のcaption
```

### figureとfigcaption

画像の直後に強調行を置くと `figure` と `figcaption` になります。caption内では
インラインMarkdownを使えます。

Markdown記法：

```markdown
![青い四角](files/sample-image.svg "サンプル画像")
*[詳しい説明](https://example.com/details)、**重要性**、`コード`を含むcaption*
```

レンダリング結果：

![青い四角](files/sample-image.svg "サンプル画像")
*[詳しい説明](https://example.com/details)、**重要性**、`コード`を含むcaption*

### ルート相対リンクとローカルファイル情報

Converterに基準URLが設定されている場合、一つの `/` から始まるリンクを補完します。
さらに設定されたドキュメントルートの配下へ安全に解決できる非画像ファイルには、
拡張子がある場合にファイル形式と容量を追記します。拡張子のないファイルは通常の
リンクのまま扱います。

Markdown記法：

```markdown
[小さなテキストファイル](/files/download.txt)
```

同梱ブラウザーサンプルでのレンダリング結果：

[小さなテキストファイル](/files/download.txt)

### note

noteは `div[role="note"]` になります。`info`、`warn`、`alert`は見た目の種別であり、
静的な `alert` 種別もARIAの `role="alert"` にはなりません。
パッケージは安定したclass名を出力しますが、note用のCSSは提供しません。視覚的な
区別が必要な場合は、利用するアプリケーションに適したCSSを用意してください。

Markdown記法：

```markdown
::: note info "参考情報"
[リンク](https://example.com/)や **構造化されたMarkdown** を含められます。
:::

::: note warn "注意"
[現在値の確認手順](https://example.com/check)を読んでから変更してください。
:::

::: note alert "重要な警告"
この操作は取り消せません。[操作上の注意](https://example.com/caution)も確認してください。
:::
```

レンダリング結果：

::: note info "参考情報"
[リンク](https://example.com/)や **構造化されたMarkdown** を含められます。
:::

::: note warn "注意"
[現在値の確認手順](https://example.com/check)を読んでから変更してください。
:::

::: note alert "重要な警告"
この操作は取り消せません。[操作上の注意](https://example.com/caution)も確認してください。
:::

### aside

周囲の本文に対して傍系となる内容に使用します。

Markdown記法：

```markdown
::: aside "関連情報"
これはネイティブの `aside` 要素になります。
:::
```

レンダリング結果：

::: aside "関連情報"
これはネイティブの `aside` 要素になります。
:::

### detailsによる開閉

タイトルはネイティブの `summary` になり、本文では構造化されたMarkdownを
使えます。タイトルを省略した場合は `Details` が既定値になります。開閉動作は
ブラウザーが提供し、外観はブラウザーやアプリケーション側のCSSによって変わります。

Markdown記法：

```markdown
::: details "説明を表示"
- 詳細の一つ目
- 詳細の二つ目
:::
```

レンダリング結果：

::: details "説明を表示"
- 詳細の一つ目
- 詳細の二つ目
:::

### コンテナーの入れ子

外側のフェンスを長くします。

```markdown
:::: aside "外側のコンテナー"
::: note info "内側のnote"
入れ子になった内容です。
:::
::::
```

## アクセシビリティとセキュリティ

- noteの種別を色だけで区別せず、意味の分かる表示ラベルを付けます。
- `aside`は傍系の内容に使い、`details`は重要な情報の発見を妨げない場合に使います。
- リンクテキストだけを読んでも、移動先が分かるようにします。
- 表のcaptionは表全体を説明し、行見出しは行方向の値を識別します。
